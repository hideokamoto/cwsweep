# Performance Requirements

| ID | 要件 | 目標値 | 根拠 |
|---|---|---|---|
| NFR1.1 | 標準規模でのスキャン完了時間 | 10アカウント×2リージョン程度で、実用上2分以内（設計目標、ハードSLAではない） | AWS APIレート制限に依存するため厳密なSLAは設定不可 |
| NFR1.2 | API呼び出し方式 | ページネーションは並列化せず、逐次呼び出しでAWSのスロットリングを尊重する | 誤ってレート制限に抵触し、他ツール・他プロセスに影響を与えることを避ける |
| NFR1.3 | メモリ使用 | 1アカウント×1リージョンあたり数百件規模のログループをメモリ上に全件保持しても実用上問題ないこと | NFR3.3（スケーラビリティ）と整合 |
| NFR1.4 | スロットリング時のリトライ・バックオフ | AWS SDKの`aws-config`標準リトライ機構（RetryMode::Standard、最大リトライ回数3回、指数バックオフ）を有効化する。リトライを使い切ってもなお`ThrottlingException`等が解消しない場合は、そのアカウント・リージョンの処理のみを失敗として扱い、NFR4.2（部分障害時の継続）に従って他アカウントの処理は継続する | AWS API呼び出しの現実的な失敗モードに対する明示的な方針。NFR4.2との境界を明確化 |

## Benchmarks

初期リリース（M1〜M5）では自動ベンチマークは必須要件とせず、Build and Testステージで実Org環境相当の統合シナリオテスト（複数アカウント×複数リージョンのモック）による動作確認を行う。
